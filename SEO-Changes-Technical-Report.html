0 The core problem this work fixes

Prior (live today)
Client-rendered React SPA. The server returns an empty shell (<div id="root"></div> + JS bundle); all content is painted by JavaScript after load. AI crawlers and render-budget-limited search crawlers saw a blank page. A ~1.8 MB entry bundle and heavy hero videos produced very poor LCP. Net: ~0% real content in the initial HTML.
Now (on deploy)
Indexable marketing routes are prerendered to static HTML at build time (SSR-equivalent snapshots), plus per-route metadata, structured data, and an AI-crawler access layer. Crawlers and LLMs get full text, titles, and schema in the raw HTML without executing JS.

1 Prerendering — the biggest single change

What: A build-time step (scripts/prerender.js) loads each marketing route in headless Chromium, lets it render and animate, then writes the fully-rendered HTML back to disk as dist/<route>/index.html. Netlify's catch-all redirect is non-forced, so these static files are served before the SPA fallback. The client still hydrates on top, so pages remain interactive.

Coverage: 23 core marketing routes + /billboard + 10 case-study pages + published blog posts pulled from Supabase at build time (graceful fallback if DB creds are absent). Utility/app routes stay client-rendered on purpose.

SEO / GEO impact
This is what makes content exist for non-JS crawlers and AI engines. It's the prerequisite for every other change in this report — titles and schema are worthless if the body is blank.

Two robustness fixes

  • Each route renders in an isolated browser context against a clean in-memory shell, so one page's injected schema can't leak into another's snapshot.
  • emptyRoot() forces the served shell's #root to be empty, so every route renders fresh rather than hydrating against stale markup — preventing a prior page's <title>/canonical from bleeding onto another route.

2 Per-route metadata

What: A lightweight head manager (src/hooks/usePageMeta.js) sets a unique <title>, meta description, rel=canonical, and Open Graph / Twitter tags per route — applied across all indexable routes, the 9 solution pages, all 10 case studies, and blog posts.

Prior
One static <title> and one description for the entire SPA — every URL shared identical metadata.
Now
Self-describing, length-appropriate title per URL (homepage trimmed to ~46 chars), unique descriptions, correct canonicals, and OG/Twitter tags.
SEO impact
Eliminates site-wide duplicate titles/descriptions (an explicit Screaming Frog finding), prevents duplicate-URL dilution via canonicals, and improves link-preview CTR on shared links.

4 GEO / AI-crawler layer

  • llms.txt added at site root (per the llms.txt spec): a structured, link-annotated map of core pages, all services, and resources, plus a one-paragraph entity summary. Validates clean.
  • robots.txt: AI crawlers (GPTBot, ClaudeBot, PerplexityBot, OAI-SearchBot, Google-Extended) remain allowed (User-agent: * / Allow: /). The only change was removing Crawl-delay: 1, which was throttling crawl budget.
  • Answer-first content: key passages restructured so the first sentence directly answers the implied question — the format AI engines preferentially extract and quote.
Prior
No llms.txt; a crawl-delay slowing crawlers; marketing-prose-first content, not answer-first.
Now
llms.txt map, unthrottled crawl, and answer-first passages.
GEO impact
llms.txt + answer-first structure directly raise citability — the likelihood an LLM quotes or recommends the site. This is the lever that moves the stated 0%-AI-citation problem.

5 Case-study pages (most recent work)

What: All 10 case studies (/work-segpro, /work-tradeworx-usa, …) were added to the prerender list and sitemap.xml, and each got usePageMeta with a unique title, a results-driven meta description, and BreadcrumbList schema. Their statistic-rich bodies (e.g. +450% campaign ROI, −85% setup time, +300% lead quality) now render into static HTML.

Prior
These routes existed but were not prerendered and not in the sitemap — crawlers/AI got the empty shell, so the hard numbers (the most citable content on the site) were invisible.
Now
Prerendered, in the sitemap, with unique metadata and breadcrumbs; numeric results live in the raw HTML.
SEO / GEO impact
Case studies are the highest-citability content an agency has — concrete, attributable, numeric results. Surfacing them in raw HTML is a direct citability and long-tail-keyword win.
Caveat to relay: in the local build these pages currently still show the homepage title, because the dev machine's build is disk-blocked and the compiled chunks are stale (they predate the usePageMeta edits). The source is correct; a clean build on the deploy pipeline produces the correct per-page titles + breadcrumb schema. This is a local-environment artifact, not a code defect.

7 Redirects, 404, sitemap, indexing control

  • sitemap.xml rebuilt to 33 static entries (core + billboard + 10 case studies), with blog posts appended at build time.
  • Legacy 301 redirect scaffold (public/_redirects) + a branded static 404.html and /404 route.
  • /free-business-audit → /marketing-audit 301 added (fixed a broken internal link).
  • /event-checkin marked noindex, follow via X-Robots-Tag in netlify.toml (utility page kept out of index and prerender).
  • Over-length titles/descriptions trimmed; duplicate-title and broken-link Screaming Frog findings resolved.
Prior
Sitemap missing case studies; no legacy-redirect map (backlinks to old URLs hit soft-404s); generic SPA 404; thin indexing control.
Now
Complete sitemap, redirect scaffold, branded 404, and explicit noindex on utility pages.
SEO impact
Better discovery, backlink-equity recovery once the legacy map is filled, no index bloat from utility pages, and clean crawls.
