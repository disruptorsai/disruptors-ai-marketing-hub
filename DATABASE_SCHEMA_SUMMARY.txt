QUESTIONS TO ANSWER
═══════════════════════════════════════════════════════════════════════

Q: Do I need to apply the Business Brain migration?
A: Depends on which features you need. Current system supports basic
   key-value facts. Migration enables semantic search, categorization,
   versioning, analytics, and multi-source intelligence.

Q: Will I lose data if I apply the migration?
A: Yes, if using the full migration script. It uses CREATE TABLE (not
   CREATE TABLE IF NOT EXISTS in some cases). Export data first, then
   re-import after migration.

Q: Can I use the current schema for production?
A: Yes, but with limitations. You won't have vector search, advanced
   categorization, source tracking, versioning, or usage analytics.
   Good for MVP, limited for scale.

Q: What's the safest migration path?
A: For production with critical data: Incremental migration (ALTER TABLE).
   For early-stage/staging: Full migration (DROP + CREATE).
   For testing only: Run migration on copy of database first.

Q: How do I enable keyword research system?
A: Primary/secondary keywords already work. To add full DataForSEO
   metadata storage, run: 20250131_add_keyword_fields_to_posts.sql

Q: What's the difference between current and expected schema?
A: Current: Simple key-value pairs, 12-field brain profile
   Expected: Structured facts with embeddings, 49-field comprehensive profile
   Gap: ~60-75% of features missing
